# Haven & Hue Interiors (Demo)

A full-stack portfolio project: a premium website for a **fictional** interior design and home renovation studio.
All company details, projects, contact information and testimonials are demonstration content.

## Features

- Responsive React + Bootstrap 5 frontend with a warm architectural design (cream, charcoal, walnut, terracotta)
- Sections: navigation, hero, services, featured projects, process, about, why choose us, sample testimonials, consultation form, contact, footer
- Project detail pages with a photo gallery and keyboard-friendly lightbox
- Consultation form with client and server validation, loading / success / error states, duplicate-submission protection, a honeypot spam trap and rate limiting
- Django admin to view and manage inquiries, and to edit services and projects (including photo uploads)
- JSON API for services, projects and consultation requests
- SEO: per-page titles, descriptions, canonical URLs, Open Graph and Twitter tags, JSON-LD structured data, sitemap.xml and robots.txt
- Accessibility: semantic HTML, skip link, labelled forms, alt text, visible focus, reduced-motion support

## Tech stack

HTML5, CSS3, JavaScript, React (Vite), Bootstrap 5, Python, Django, Django REST Framework, SQLite

## Project structure

- `backend/` - Django project (`config/`) and apps: services, projects, consultations, seo
- `frontend/` - React app (Vite): components, pages, styles, API client
- `deploy/` - Example Nginx, gunicorn and production .env files

## Local setup

Requirements: a recent Python 3 (3.12+ recommended) and Node.js 20.19+ (LTS).
Keep the project in a folder path **without an ampersand** (it breaks npm on Windows) and ideally outside OneDrive.

### 1. Backend (Windows PowerShell)

    cd backend
    python -m venv venv
    venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    copy .env.example .env

On macOS / Linux use `python3 -m venv venv`, `source venv/bin/activate` and `cp .env.example .env`.

Generate a secret key and paste it into `backend/.env` as `DJANGO_SECRET_KEY`:

    python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"

Create the database and demo data, then start the server:

    python manage.py migrate
    python manage.py createcachetable
    python manage.py createsuperuser
    python manage.py seed_demo_data
    python manage.py runserver

The API and admin run at http://127.0.0.1:8000 (admin at `/admin/`).

### 2. Frontend (second terminal)

    cd frontend
    copy .env.example .env
    npm install
    npm run dev

The site runs at http://localhost:5173. Vite proxies `/api`, `/sitemap.xml` and `/robots.txt` to Django.
Run `python manage.py ...` only inside `backend`, and `npm ...` only inside `frontend`.

## Environment variables

Backend (`backend/.env`):

| Variable | Purpose |
|---|---|
| DJANGO_SECRET_KEY | Django secret key. Required. Never commit it. |
| DJANGO_DEBUG | True in development, False in production. |
| DJANGO_ALLOWED_HOSTS | Comma-separated host names. |
| CORS_ALLOWED_ORIGINS | Frontend origins allowed to call the API. |
| CSRF_TRUSTED_ORIGINS | Trusted origins for the admin over HTTPS. |
| FRONTEND_URL | Public site address, used in sitemap.xml and robots.txt. |
| NUM_PROXIES | Reverse proxies in front of Django (0 locally, 1 behind Nginx). |

Frontend (`frontend/.env`): `VITE_API_BASE_URL` (leave empty when the API is on the same domain) and `VITE_SITE_URL` (public site address, used for canonical URLs and share images). These values are public. Never put secrets in frontend variables.

## Managing content in the admin

1. Open `/admin/` and log in.
2. **Projects**: add or edit a project, upload the cover image, and add gallery photos in the table at the bottom (each needs alt text and an order). Untick *Is active* to hide a project without deleting it.
3. **Services**: edit titles, descriptions and order.
4. **Consultation requests**: review inquiries, set their status (new, contacted, closed) and add internal notes.

Photos accept JPG, PNG or WebP up to 5 MB. About 1600 px wide is a good size.
The homepage photo, studio contact details and social links are edited under **Site settings** in the admin (leave a social link empty to hide its icon).

## API

| Method | Endpoint | Purpose |
|---|---|---|
| GET | /api/services/ | Active services |
| GET | /api/projects/ | Active projects (add ?featured=true for featured only) |
| GET | /api/projects/{slug}/ | One project with its gallery |
| GET | /api/site-settings/ | Homepage photo, contact details and social links |
| POST | /api/consultations/ | Submit a consultation request (JSON, rate limited) |
| GET | /sitemap.xml, /robots.txt | SEO files generated by Django |

## Security notes

- Secrets and environment-specific settings are read from environment variables, not source code.
- Server-side validation on every form field, with duplicate-request detection and a honeypot field.
- Rate limiting on the consultation endpoint (5 per hour per visitor, using a shared database cache).
- The public form API uses no cookies or sessions. CORS is limited to the configured origins. CSRF protection stays active for the admin.
- In production (DJANGO_DEBUG=False) HTTPS redirect, secure cookies, HSTS and content-type protection are enabled.
- Uploaded images are restricted by type and size and verified as real images.
- Run `python manage.py check --deploy` with production settings before going live.

## Deployment overview

Simplest setup: one Linux server with Nginx serving the React build and photos, and gunicorn running Django, all on one domain (no CORS needed). Examples are in `deploy/`.

### 1. Build the frontend

On your computer, with your real domain:

    cd frontend
    $env:VITE_SITE_URL="https://yourdomain.com"; npm run build

Upload the contents of `frontend/dist` to `/var/www/haven-hue/frontend`.

### 2. Backend on the server

Copy `backend/` to `/srv/haven-hue/backend`, create a venv and run `pip install -r requirements.txt`. Copy `deploy/backend.env.production.example` to `backend/.env` and edit it. Then run:

    python manage.py migrate
    python manage.py createcachetable
    python manage.py collectstatic --noinput
    python manage.py createsuperuser

The `www-data` user needs write access to the `backend` folder (for db.sqlite3) and to `backend/media`.

### 3. gunicorn and Nginx

Install `deploy/haven-hue.service.example` as a systemd service and `deploy/nginx.conf.example` as the Nginx site. Point your domain's DNS at the server, then get HTTPS with Certbot. Get the certificate **before** setting DJANGO_DEBUG=False, because Django then redirects all traffic to HTTPS.

### 4. After launch

Open `/sitemap.xml`, submit it in Google Search Console, and test pages with Google's Rich Results Test.

### 5. Backups

Copy `backend/db.sqlite3` and `backend/media/` regularly. SQLite is fine for a low-traffic portfolio or small business site. Move to PostgreSQL if traffic or write volume grows.

### Alternative hosting

Host the frontend on a static host (Netlify, Vercel) and the backend on a Python host. Then set `VITE_API_BASE_URL` to the backend's `/api` address, add the frontend's address to CORS_ALLOWED_ORIGINS and CSRF_TRUSTED_ORIGINS, and store uploaded photos on persistent or cloud storage.

## Testing checklist

- [ ] Empty form shows errors under each field
- [ ] Valid submission shows the success panel and appears in the admin
- [ ] Repeating the same email and project type within 10 minutes is rejected
- [ ] More than 5 submissions in an hour are rate limited
- [ ] Stopping the backend shows a friendly "unable to reach the server" message
- [ ] Project pages, gallery lightbox and mobile menu work
- [ ] /sitemap.xml and /robots.txt load
- [ ] Lighthouse run on mobile (record the scores you actually get)

## Known limitations

- Link previews on WhatsApp, Facebook, LinkedIn and X do not run JavaScript, so a shared project link shows the homepage preview. Google does run JavaScript. Pre-rendering project pages would fix this.
- Consultation requests are stored and viewed in the admin. Email notifications are not set up.
- Contact details, social links, company and projects are fictional placeholders. Testimonials are labelled samples. Replace all of them, and add real structured-data details (phone, address, hours), when building for a real client.
